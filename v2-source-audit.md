# v2 open-data and licensing audit

**Review date:** 2026-10-10  
**Status:** preliminary source screen; no new factor source is cleared for integration. The existing Carbonfact v1.1.0 release remains the only bundled source. No candidate dataset archive or new factor values were added to the repository.

This audit is an eligibility screen, not a finding that every source in a collection has been exhaustively verified. Dataset-level metadata is not a substitute for checking the exact files, their upstream providers, and the rights for each dependency.

## Integration gate

Before adding any factor data, the selected version and files must have:

1. Explicit rights to redistribute the exact data and any derived values, plus required attribution and share-alike notices.
2. A recorded version, source citation, geography, temporal coverage, declared/reference unit, and process boundary.
3. A documented provider/dependency graph and method. Ecoinvent-linked data are not available for integration without evidence of a license that permits the intended access, processing, and redistribution. Do not bypass those terms or reconstruct a proprietary inventory. The already-pinned Carbonfact published scores remain unchanged and are outside this source-integration screen.
4. Indicator definitions, characterization method, and units that can be used without presenting an unmatched process or indicator as equivalent to the existing EF 3.1 factors.
5. Reproducible values and provenance at the individual process/indicator level. Selected-row totals and the EF 3.1 single score are now authorized and implemented for the existing data, but they do not establish product completeness or clear a new source for integration.

## EF 3.1 normalisation and weighting verification

Primary-source review on 2026-10-10 confirms the values currently used by `apps/web/src/ef31-score.ts`:

- The official [JRC EF 3.1 workbook](https://eplca.jrc.ec.europa.eu/permalink/EF3_1/Normalisation_Weighting_Factors_EF_3.1.xlsx), `NFs EF3.1` sheet, lists all 16 global per-person normalisation factors. The values in code and `data-sources.md` match the sheet to its reported precision.
- The JRC [2018 EF weighting report](https://eplca.jrc.ec.europa.eu/permalink/2018_JRC_Weighting_EF.pdf) recommends a final weighting set that applies category-specific robustness factors and scales the resulting factors to 100. Its all-category table gives these final percentages: ACD 6.20, ETF 1.92, FRU 8.32, FWE 2.80, GHG 21.06, HTC 2.13, HTN 1.84, IOR 5.01, LDU 7.94, MRU 7.55, OZD 6.31, PCO 4.78, PMA 8.96, SWE 2.96, TRE 3.71, and WTU 8.51. They match the implementation and sum to 100% (subject to floating-point display precision).
- The same report also gives an alternative final set excluding three toxicity-related categories. The application deliberately uses the **all-category** set because it calculates a score across all 16 indicators; that choice and its source are disclosed in the UI and data table. The report frames weighting as a value choice and discusses robustness; the single score must not replace review of the separate indicators.
- The JRC [2023 guide to the Member States Consumption Footprint Tool](https://eplca.jrc.ec.europa.eu/uploads/JRC132621_MS_guide.pdf) independently states that its single weighted score aggregates 16 impact categories using EF 3.1 normalisation factors and the EF weights proposed in Sala et al. (2018), corroborating the selected factor pairing.

The separate normalization-workbook and weighting-report citations remain in the UI and CSV. These method checks verify only the aggregation constants and cited calculation basis, not process-factor coverage, product composition, or completeness.

## USDA collection finding

The USDA collection merits further review: it contains an actual cotton field-crop unit-process inventory, not merely a blank modeling template. Its public-domain label and open process files make version 2 a possible *foreground LCI* candidate, but do not make it a complete impact-factor dataset. The separate version-1 crosswalk explicitly points to ecoinvent 2.2; that crosswalk is excluded. The version-2 archive’s complete provider graph has not been inspected, so it is not yet possible to certify that a calculation based on it can be completed without a non-open dependency. No values have been mapped to an apparel input or added to the API.

## Result and next step

No newly reviewed process-factor source passes the complete licensing, provenance, boundary, and method gate for integration. Continue with the version-2 USDA file-level dependency audit and exact reuse terms for the 2026 cotton studies. Before integrating a source, record its version, geography, time coverage, unit, boundary, provider graph, per-indicator method, attribution, and test fixtures. The browser now provides an explicitly selected-row subtotal and EF 3.1 score using the JRC workbook; this does not clear a new factor source or certify complete product coverage.
